---
description: ブランチ運用の制約
---

- `main` / `master` へ直接コミット・直接 push しない
- 変更は Issue → `issue-<番号>/<説明>` ブランチ → PR（`Closes #N`）→ squash merge → ブランチ削除 の順で行う
- この制約は指示だけに頼らず、フック（`block-main-push.sh`）と GitHub のブランチ保護で担保する

## GitHub リモート未作成の間の暫定運用

- リモート未作成の間は Issue も PR も存在しないため、上記の正規フローは適用できない。ブランチだけローカルで規約に寄せる:
  - `feature/<簡単な説明>`（番号なし）ブランチを切って作業し、完了したら `git merge --squash` で `main` に取り込んでブランチを削除する
  - `main` への直接コミットはしない(暫定運用開始後)
- `block-main-push.sh` はリモートへの `push` のみをブロックする実装のため、リモート未作成の現状では実質的な歯止めにならない。ローカル直コミットを避けるのは運用上の約束であり、フックには頼らない
- リモートを作成したら、この節を削除し、以降の作業は正規の `issue-<番号>/<説明>` → PR フローに切り替える
